# 五池模块化架构

用户入口是 DeviLudo 项目工作台，而非资源池控制台。Web 通过 BFF 调用 Core 的项目、规格和工作流接口；五池页面仅为后台运维诊断。

公网请求只能进入 `WEB`，由其转发页面会话和流式 API 响应到 `CORE`。Web 容器没有数据服务或执行节点凭据。

Core 使用同一镜像，并通过启动角色拆分权限：

| 角色 | 责任 | 数据库角色 |
| --- | --- | --- |
| `api` | 身份、项目、配置、管理、推理与业务接口 | `deviludo_api` |
| `scheduler` | 工作流推进、租约恢复、重试与容量意图 | `deviludo_scheduler` |
| `sandbox` | Agent microVM、受限构建、发布上传 | `deviludo_sandbox` |

E2E 节点只通过出站 mTLS 访问 Core。每台物理节点同时只绑定一个租户；每项作业要求前置重镜像证明、清理证明和后置重镜像证明。测试执行器从不接收签名授权；只有平台匹配的签名执行器可领取五分钟以内的一次性包装授权。

所有租户表强制行级隔离，跨表关系均携带 `tenant_id`。跨租户 claim 函数由无登录的收窄角色持有，应用角色都没有绕过行级隔离的权限。
